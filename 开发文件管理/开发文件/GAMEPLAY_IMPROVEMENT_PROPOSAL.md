## 一、项目概述

### 1.1 项目背景

当前游戏存在以下核心问题：

| 问题类型 | 具体表现 | 影响分析 |
|---------|---------|---------|
| **进度过高** | 每周进度15%，12周可达180% | 通关时间过短，缺乏挑战 |
| **B2C缺失** | 缺少商家数指标和招商玩法 | B2C模式体验不完整 |
| **重复性高** | 每周固定三次选择，流程机械 | 降低游戏新鲜感 |
| **缺乏随机性** | 事件按顺序循环出现 | 可预测性强，策略深度不足 |
| **缺乏真实感** | 忽略节假日等现实因素 | 沉浸感不足 |
| **卡牌冗余** | 员工卡与谈判卡牌存在冗余 | 体验割裂 |

### 1.2 核心目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| 平衡进度 | 平均通关时间6-8个季度 | 🔴 高 |
| B2C商家系统 | 新增商家数指标和招商玩法 | 🔴 高 |
| 偶发事件 | 增加游戏随机性和沉浸感 | 🔴 高 |
| 卡牌整合 | 双光谱卡牌系统，消除冗余 | 🟡 中 |

| 角色Buff | 季节/节日专属效果 | 🟡 中 |

## 二、核心玩法优化

### 2.1 进度平衡调整

**问题**：每周进度15%，12周可达180%，进度过快

**解决方案**：
- **基础进度值**：从5%降低到3%
- **动态事件次数**：根据士气自动调整

| 游戏状态 | 每周事件次数 | 效果乘数 | 周进度预期 |
|---------|-------------|---------|-----------|
| 高士气（≥80） | 2次 | ×1.5 | 9% |
| 正常状态 | 3次 | ×1.0 | 9% |
| 低士气（≤40） | 4次 | ×0.8 | 9.6% |

**平衡计算**：
- 季度进度：9%/周 × 12周 = 108%
- 6个季度总进度：6 × 108% = 648%
- 扣除节假日和负面事件影响，实际通关时间约6-8个季度

### 2.2 纯偶发事件系统（无选项版）

**设计理念**：增加游戏随机性和沉浸感

| 事件类型 | 触发时机 | 效果特点 | 示例场景 |
|---------|---------|---------|---------|
| **环境事件** | 每周随机（20%概率） | 轻微正面/负面效果 | 天气影响、办公室氛围 |
| **机遇事件** | 进度里程碑、高满意度 | 纯正面效果 | 意外收获、免费资源 |
| **危机事件** | 低满意度、随机触发 | 纯负面效果 | 突发故障、意外开支 |
| **彩蛋事件** | 特定条件触发 | 趣味性效果 | 节日彩蛋、隐藏剧情 |

**事件数据结构**：
```json
{
    "id": "random_event_001",
    "title": "阳光明媚的一天",
    "type": "environment",
    "triggerCondition": {
        "probability": 0.2,
        "minWeek": 1,
        "maxWeek": 52
    },
    "autoEffects": {
        "morale": 3
    },
    "weeklyEffect": "团队士气略有提升"
}
```

**触发机制**：
```
每周开始时：
  ├─ 检查偶发事件触发条件
  │   ├─ 随机概率判定（20%-30%）
  │   └─ 满足特定条件（满意度、进度、周数等）
  ├─ 若触发成功：
  │   ├─ 显示事件弹窗（仅展示，无选项按钮）
  │   ├─ 自动应用效果到游戏状态
  │   └─ 记录到周日志
  └─ 继续正常事件流程
```

**模式差异化设计**：
| 模式 | 环境事件主题 | 机遇事件主题 | 危机事件主题 |
|------|-------------|-------------|-------------|
| **ToB** | 甲方来访、合同审批、招标信息 | 客户转介绍、合同续签、政策利好 | 客户投诉、项目延期、回款困难 |
| **ToC** | 应用商店推荐、社区热议、KOL关注 | 下载量爆发、好评如潮、融资机会 | 应用下架、服务器崩溃、负面报道 |
| **B2C** | 商家入驻、流量增长、政策支持 | 头部商家入驻、GMV突破、品牌合作 | 商家抗议、用户投诉、监管约谈 |

## 三、B2C商家系统

### 3.1 商家招商会小游戏

**推荐方案**：方案A（卡牌谈判系统）

**游戏流程**：
1. 【发牌阶段】玩家抽取3张谈判手牌
2. 【商家出招】展示商家需求（资金/流量/技术）
3. 【玩家出牌】选择手牌应对（可出1-3张）
4. 【判定阶段】卡牌效果+资源匹配度+好感度=成功率
5. 【奖励阶段】成功则商家入驻

**谈判牌库**：
| 卡牌名称 | 类型 | 效果 | 稀有度 |
|---------|------|------|--------|
| 价格战 | 资金 | 资金需求-50% | R |
| 流量扶持 | 流量 | 流量需求-50% | R |
| 技术支持 | 技术 | 技术需求-50% | R |
| 组合拳 | 组合 | 随机降低两项需求 | SR |
| 杀手锏 | 特殊 | 成功率+30% | SR |
| 必杀技 | 特殊 | 必定成功（限1次） | SSR |

**商家类型**：
| 类型 | 入驻奖励 | 资金需求 | 流量需求 | 技术需求 | 基础成功率 |
|------|---------|---------|---------|---------|-----------|
| 普通商家 | +5 | 5 | 3 | 2 | 80% |
| 优质商家 | +15 | 8 | 5 | 4 | 60% |
| 头部商家 | +30 | 12 | 8 | 6 | 40% |

### 3.2 成功率计算公式

```
最终成功率 = 基础成功率 
            + 卡牌效果加成 
            + 资源匹配度加成（每项满足+10%） 
            + 小葵好感度加成（≥80时+10%） 
            + 连击加成（连续成功+5%/次，最高+15%）

上限：95%
下限：5%
```

### 3.3 连击系统

| 连击次数 | 加成 |
|---------|------|
| 1次 | +5% |
| 2次 | +10% |
| 3次+ | +15%（上限） |

## 五、新增核心机制

### 5.1 卡牌磨损机制（不可逆设计）

**设计理念**：反映互联网行业真实情况，员工疲惫无法用金钱修复

**磨损规则**：
| 使用场景 | 磨损程度 |
|---------|---------|
| 报表对决被克制失败 | -1 |
| 招商小游戏成功 | -1 |
| 招商小游戏失败 | -2 |
| SSR特殊卡牌 | -3 |

**初始耐久度**：
| 稀有度 | 初始耐久度 | 分解碎片 |
|-------|---------|---------|
| R | 10 | 1 |
| SR | 8 | 3 |
| SSR | 5 | 10 |

**报废处理**：
- 耐久度=0 → 卡牌报废（员工离职/考公）
- 报废卡牌可分解为碎片
- 50碎片=R卡，100碎片=SR卡，300碎片=SSR卡

### 5.2 动态抽卡成本（U型曲线）

**公式**：
```
抽卡成本 = 基础成本 × 名声系数 × 资金系数

- 基础成本：R卡1000，SR卡5000，SSR卡15000
- 名声系数：1.0 - (名声/200)  [最低0.5]
- 资金系数：1.0 + (资金/资金阈值) × 0.5  [最高1.7]
```

**资金阈值**：
| 阶段 | 资金阈值 |
|------|---------|
| 前期（1-4季度） | 5万 |
| 中期（5-8季度） | 20万 |
| 后期（9+季度） | 50万 |

**抽卡机制**：本游戏采用**纯几率抽卡**，无保底机制，还原真实招聘可遇不可求的特点。

### 5.3 HC动态调整（里程碑解锁）

**通用里程碑**：

```javascript
function getWeeklyEventCount() {
```

```javascript
function applyCardWear(cardId, scenario, success) {
    const card = getCardById(cardId);
    if (card.currentDurability <= 0) {
        showNotification(`卡牌"${card.name}"已报废！`);
        return false;
    }
    
    let wearAmount = scenario === 'negotiation' ? (success ? 1 : 2) : 1;
    card.currentDurability -= wearAmount;
    
    if (card.currentDurability === 0) {
        showNotification(`卡牌"${card.name}"已报废（离职/考公）！`);
    }
    return true;
}
```
