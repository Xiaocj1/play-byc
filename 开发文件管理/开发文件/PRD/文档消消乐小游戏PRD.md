## 一、产品概述

### 1.1 产品定位

文档消消乐是**嵌入式小游戏**，作为**事件选项的替代玩法**。当玩家选择"加班写PRD"、"做用户调研"等选项时，触发消消乐小游戏，成功完成后获得更好的奖励。

### 1.2 目标用户

- 核心用户：喜欢休闲小游戏的玩家
- 潜在用户：对"写文档"有共鸣的职场人

### 1.3 核心价值

- **讽刺感**：还原"写了一堆文档，结果都没用"的真实体验
- **策略深度**：用户调研会消失，需要优先级判断
- **解压**：消除文档的爽感

### 2.2 游戏机制

#### 2.2.1 棋盘设计

- **棋盘大小**：4×4（16格）
- **文档类型**：4种基础文档 + 2种特殊文档

| 文档类型 | 图标 | 颜色 | 作用 | 特殊机制 |
|---------|------|------|------|----------|
| 📄 PRD | PRD | 蓝色 | 进度+ | 无 |
| 📋 需求文档 | 需求 | 灰色 | 进度+ | 无 |
| 🔍 用户调研 | 调研 | 绿色 | 满意度+ | **30%概率消失** |
| 📊 BP | BP | 金色 | 融资进度+ | 无 |
| 💥 祖传代码 | 代码 | 红色 | 消除周围 | 随机出现 |
| ✨ 灵感 | 灵感 | 彩虹 | 万能匹配 | 稀有（5%） |

#### 2.2.2 消除规则

- **基础消除**：3个相同文档连成一线（横/竖）→ 消除
- **连锁消除**：消除后上方文档掉落，新文档补充，可能触发新的3连 → 连击加分
- **Combo奖励**：
  - 3连击 → 分数×2
  - 5连击 → 分数×3
  - 10连击 → 分数×5，但压力+10

#### 2.2.3 "用户调研消失"机制

**触发条件**：
- 用户调研文档生成时，有30%概率标记为"将消失"
- 用户调研文档在棋盘上停留超过3回合 → 自动消失

**视觉表现**：
- 标记为"将消失"的调研文档，增加闪烁动画
- 消失时播放"啪"的动画（文档碎裂）

**讽刺文案**（消失时显示）：
```
用户调研已失效
原因：用户说不清楚需求
（其实是产品经理没听懂）
```

#### 2.2.4 步数限制

- 每局有固定步数（15-30步，根据事件难度）
- 步数用完时：
  - 达成目标 → 成功
  - 未达成目标 → 失败

**步数提示**：
- 剩余步数 > 10 → 绿色
- 剩余步数 5-10 → 黄色
- 剩余步数 < 5 → 红色闪烁

#### 2.2.5 进化链机制（新增）

**核心概念**：消除3个相同的基础资源时，会在匹配位置生成对应的高级文档。

**进化关系表**：

| 基础资源 | 图标 | 进化产物 | 图标 |
|---------|------|---------|------|
| ✨ 灵感 | 灵感 | 📄 PRD文档 | PRD |
| 📋 需求 | 需求 | 📋 需求文档 | 需求文档 |
| 👥 用户 | 用户 | 🔍 用户调研 | 调研 |

**触发条件**：
- 横向或纵向连续消除3个相同类型的基础资源
- 消除后在匹配组的**最左/最上位置**生成进化产物

**位置规则**：
- **横向消除**：在三个位置中**列号最小**的位置生成（最左边）
- **纵向消除**：在三个位置中**行号最小**的位置生成（最上边）

**特殊规则**：
1. **交点合并**：当5个连成一条线或T字形等有交点的情况，只生成1个进化产物
2. **连锁独立**：连锁消除的每一轮都是独立事件，各自生成产物
3. **产物参与**：进化产物会参与下一轮消除

**执行顺序**：
```
消除 → 统计类型 → 判断是否触发进化 → 在指定位置放置进化产物 → 掉落填充 → 检查连锁
```

**示例**：
```
初始状态：✨ ✨ ✨
         📋 📋 📋
         
第一步消除：✨ ✨ ✨ → 生成 📄PRD（在最左边位置）
           📋 📋 📋 → 生成 📋需求文档（在最左边位置）
           
结果状态：📄 📋 ✨
         📋 📋 ✨
```

**策略深度**：
- 玩家会主动规划消除顺序，优先消除基础资源获得高级文档
- 直接支持"收集PRD"的游戏目标，让玩法更有目的性
- 增加"合成"的成就感，类似开心消消乐的特效道具

#### 2.2.6 难度设计

**目标分布**（玩家成功率）：

| 玩家类型 | 占比 | 描述 | 完成度 | 结果 |
|----------|------|------|--------|------|
| 极限完成 | 65% | 最后两步才能收集到 | 100% | 成功（紧张刺激） |
| 差一点 | 10% | 死在差一点 | 90-99% | 失败（可重来） |
| 超额完成 | 10% | 超额完成，有概率获得额外奖励 | >100% | 成功（有概率额外奖励） |
| 无重来资格 | 15% | 完成度太低 | <80% | 失败（不可重来） |

**实现方式**：

通过调整以下参数，达到目标分布：

1. **棋盘生成算法**：
   - 控制可消除的3连数量
   - 控制目标文档的出现概率
   - 控制"用户调研消失"的概率

2. **步数计算**：
   - 目标文档数量：N
   - 每步平均消除文档数：M
   - 所需步数：N / M × 1.2（预留20%冗余）
   - 总步数：所需步数 × 1.1（让65%的人最后两步完成）

3. **动态难度调整**（见3.3节）：
   - 根据玩家历史表现，动态调整难度
   - 连续成功 → 增加难度
   - 连续失败 → 降低难度

**示例配置**（目标：消除5个PRD）：

```
基础配置：
- 棋盘大小：4×4
- PRD出现概率：40%
- 每步平均消除：1.5个PRD
- 所需步数：5 / 1.5 × 1.2 = 4步
- 总步数：4 × 1.1 = 4.4 → 5步

调整后（让65%的人最后两步完成）：
- 总步数：7步
- PRD出现概率：35%（降低）
- 用户调研消失概率：30%（增加不确定性）
```

**调试工具**（见3.3节）：
- 实时调整PRD出现概率
- 实时调整步数
- 实时调整用户调研消失概率
- 查看玩家分布统计

### 3.2 核心算法

#### 3.2.1 棋盘初始化

```javascript
function initBoard() {
  const board = []
  for (let i = 0; i < 4; i++) {
    board[i] = []
    for (let j = 0; j < 4; j++) {
      board[i][j] = randomDocType()  // 随机生成文档
      // 用户调研有30%概率标记为"将消失"
      if (board[i][j] === '调研' && Math.random() < 0.3) {
        board[i][j].willDisappear = true
      }
    }
  }
  return board
}
```

#### 3.2.2 消除检测

```javascript
function checkMatch(board) {
  const matched = []
  
  // 检测横向3连
  for (let i = 0; i < 4; i++) {
    for (let j = 0; j < 2; j++) {
      if (board[i][j] === board[i][j+1] && board[i][j] === board[i][j+2]) {
        matched.push([i, j], [i, j+1], [i, j+2])
      }
    }
  }
  
  // 检测纵向3连
  for (let i = 0; i < 2; i++) {
    for (let j = 0; j < 4; j++) {
      if (board[i][j] === board[i+1][j] && board[i][j] === board[i+2][j]) {
        matched.push([i, j], [i+1, j], [i+2, j])
      }
    }
  }
  
  return matched
}
```

#### 3.2.3 用户调研消失

```javascript
function checkDisappear(board, turn) {
  for (let i = 0; i < 4; i++) {
    for (let j = 0; j < 4; j++) {
      if (board[i][j].type === '调研') {
        // 生成时标记为将消失
        if (board[i][j].willDisappear && turn - board[i][j].createdTurn >= 3) {
          board[i][j] = null  // 消失
          playDisappearAnimation(i, j)
        }
      }
    }
  }
}
```

#### 3.3.3 动态难度调整算法

**玩家表现追踪**：
```javascript
const playerStats = {
  recentGames: [],  // 最近10局的结果
  averageCompletion: 0,  // 平均完成度
  winStreak: 0  // 连胜次数
}

function adjustDifficulty() {
  const stats = playerStats
  
  // 连续成功 → 增加难度
  if (stats.winStreak >= 3) {
    config.prdProbability -= 0.05
    config.totalMoves -= 2
  }
  
  // 连续失败 → 降低难度
  if (stats.recentGames.filter(g => !g.success).length >= 3) {
    config.prdProbability += 0.05
    config.totalMoves += 2
  }
}
```

## 四、开发规范（新增）

### 4.1 模块拆分原则

**按功能拆分，建立代码-功能映射关系**，方便后续修改和维护。

#### 4.1.1 目录结构

```
src/components/minigames/Match3Game/
├── Match3Game.vue          # 主入口组件（组装所有子组件）
├── Match3Board.vue         # 棋盘组件（渲染4×4格子）
├── Match3Cell.vue          # 单个格子组件（渲染文档图标）
├── Match3Goal.vue          # 目标面板（显示"消除5个PRD"）
├── Match3Moves.vue         # 步数面板（显示剩余步数）
├── Match3Result.vue        # 成功/失败界面
├── Match3Debug.vue        # 调试面板（Ctrl+Shift+D调出）
└── composables/
    ├── useBoard.js         # 棋盘逻辑（初始化、重排、死局检测）
    ├── useMatch.js         # 消除逻辑（检测3连、执行消除、连锁反应）
    ├── useDisappear.js    # 消失逻辑（用户调研消失机制）
    ├── useMoves.js        # 步数逻辑（消耗、判定用完）
    ├── useGoal.js          # 目标逻辑（计数、达成判定、重试机制）
    ├── useDifficulty.js   # 难度逻辑（动态难度调整、参数计算）
    └── useDebug.js        # 调试逻辑（参数调整、模拟、API）
```

#### 4.1.2 模块依赖关系

```
useBoard（棋盘最核心，其他模块都依赖它）
   ↓
useMatch（消除逻辑，依赖棋盘）
   ↓
useDisappear（消失逻辑，依赖棋盘）
   ↓
useMoves（步数逻辑，独立）
   ↓
useGoal（目标逻辑，依赖消除结果）
   ↓
useDifficulty（难度逻辑，调整上方模块的参数）
   ↓
Match3Debug（调试面板，调用所有模块的debug API）
```

**开发顺序**：按依赖顺序实现，先实现底层模块，再实现上层模块。

### 4.6 性能优化建议

1. **棋盘渲染优化**：
   - 使用`v-memo`指令（Vue 3.2+），避免不必要的重新渲染
   - 对于静态格子，使用`v-once`指令

2. **消除计算优化**：
   - 只在交换后检测相关行/列，而不是全棋盘扫描
   - 使用Web Worker处理复杂计算（可选）

3. **动画性能优化**：
   - 使用CSS动画（GPU加速）代替JS动画
   - 对于大量动画，使用`requestAnimationFrame`

4. **内存优化**：
   - 及时销毁不再使用的定时器/监听器
   - 对于大对象，使用`shallowRef`代替`ref`

| 步数限制 | 步数用完时正确结算 | P0 |
| 成功/失败判定 | 达成目标→成功，否则→失败 | P0 |
| 奖励应用 | 成功/失败后正确应用effects | P0 |
| 动画效果 | 消除、掉落、连击动画流畅 | P1 |
| 音效 | 消除、连击、成功/失败音效 | P2 |

### 5.2 性能验收

- 消除计算耗时 < 100ms
- 动画帧率 > 30fps
- 内存占用 < 50MB

### 5.3 兼容性验收

- Chrome/Edge/Safari 最新版兼容
- 移动端适配（触摸操作）

### 5.4 边界验收

| 边界场景 | 验收标准 | 优先级 | 备注 |
|----------|----------|--------|------|
| 连锁消除 | 自动触发，不消耗额外步数，文档累计到目标 | P0 | 参考开心消消乐 |
| 死局检测 | 无可能匹配时，自动重排棋盘，不消耗步数 | P0 | 只和自动的重排步数和收集度有关 |
| 用户调研消失 | 每步走完时自动触发消失（没有步数的操作不会触发消失） | P0 | 回合结束触发 |
| 消失文案显示 | 固定1.5秒，在上方提示，不影响玩家操作 | P1 | 先看看效果 |
| 最后一步连锁 | 步数为0时，连锁消除仍然有效，算成功 | P0 | 关键边界 |
| 步数用完未达成目标 | 直接算失败，但完成80%可以重来一次 | P0 | 失败后可选择重试 |
| 祖传代码爆炸 | 待定 | P2 | 后续讨论 |
| 灵感匹配 | 类似开心消消乐的万能牌，这一类都消除，消耗一次行动点 | P0 | 万能牌机制 |
| 小游戏中断 | 点击"放弃"后显示确认弹窗 | P1 | 游戏打算打包上Steam单机 |
| 超额完成 | 10%的概率有效（具体数值乘基础数值） | P1 | 平衡性调整 |

#### 5.4.1 连锁消除详细规则

**触发时机**：
- 玩家完成一次交换后，自动检测并触发连锁消除
- 连锁消除过程中，不允许玩家操作

**步数消耗**：
- 连锁消除不消耗额外步数
- 只有玩家的主动交换才消耗步数

**目标计数**：
- 连锁消除的文档，累计到目标计数
- 例如：目标消除5个PRD，连锁消除共消除3个PRD → 当前进度：3/5

#### 5.4.2 死局检测详细规则

**检测时机**：
- 每次消除完成后，检测是否有可能的匹配
- 如果无任何可能的3连组合，判定为死局

**重排规则**：
- 死局时，自动重新生成棋盘
- 重排不消耗步数
- 重排后，重新检测是否有可能的匹配（避免再次死局）

**重排动画**：
- 棋盘淡出（0.3秒）
- 重新生成棋盘
- 棋盘淡入（0.3秒）

#### 5.4.3 用户调研消失详细规则

**触发时机**：
- 每步操作完成后（交换 + 消除 + 掉落完成）
- 检测用户调研文档是否需要消失

**消失条件**：
- 用户调研文档生成时，有30%概率标记为"将消失"
- 每步操作后，检测标记为"将消失"的调研文档，有30%概率消失

**消失动画**：
- 文档闪烁（0.5秒）
- 文档碎裂效果（0.3秒）
- 上方文档掉落填补空位

**文案显示**：
- 消失时在棋盘上方显示文案："用户调研已失效"
- 固定显示1.5秒，然后自动消失
- 文案显示不影响玩家操作（非模态）

#### 5.4.4 最后一步连锁详细规则

**场景**：
- 玩家剩余1步，执行交换后触发消除
- 消除后掉落，触发连锁消除
- 连锁消除过程中，步数变为0

**判定规则**：
- 连锁消除仍然有效
- 连锁消除的文档累计到目标
- 如果达成目标，判定为成功

**示例**：
```
剩余步数：1
目标：消除5个PRD
当前进度：3/5

玩家执行交换 → 触发消除（消除3个PRD）
进度：6/5（达成目标）
连锁消除触发 → 再消除2个PRD
进度：8/5

判定：成功（达成目标）
```

#### 5.4.5 步数用完未达成目标详细规则

**失败判定**：
- 步数用完时，未达成目标 → 判定为失败

**重来机制**：
- 如果完成度 ≥ 80%，显示"重来一次"按钮
- 完成度 = 当前进度 / 目标进度
- 例如：目标5个，完成4个 → 完成度80% → 可以重来

**重来规则**：
- 点击"重来一次" → 重置步数为初始值
- 棋盘状态保持原样（不重新生成）
- 目标进度保持原样

#### 5.4.6 灵感（万能牌）详细规则

**匹配规则**：
- 灵感可以代替任何文档类型
- 例如：📄 ✨ 📄 → 可以消除（✨代替📄）
- 例如：📄 ✨ 📊 → 不能消除（✨两边类型不同）

**消除规则**：
- 灵感参与匹配后，被消除
- 消耗一次行动点（步数）

**连击规则**：
- 灵感被消除后，可以触发连锁消除
- 连锁消除的文档累计到目标

#### 5.4.7 小游戏中断详细规则

**中断时机**：
- 玩家点击"放弃"按钮

**确认弹窗**：
- 显示确认弹窗："确定要放弃吗？当前进度将不会保存。"
- 选项：["确定放弃", "继续游戏"]

**放弃处理**：
- 点击"确定放弃" → 关闭小游戏
- 应用失败惩罚（failEffects）
- 返回事件卡片

**Steam单机保存**：
- 游戏状态自动保存到localStorage
- 玩家可以关闭游戏，下次继续

#### 5.4.8 超额完成详细规则

**超额判定**：
- 达成目标后，继续消除文档 → 超额完成

**奖励规则**：
- 超额完成有10%概率有效
- 如果有效，额外奖励 = 基础奖励 × (完成数 - 目标数) / 目标数
- 例如：目标5个，完成8个，基础奖励10
  → 超额3个，10%概率有效
  → 如果有效，额外奖励 = 10 × 3/5 = 6
  → 总奖励 = 10 + 6 = 16

**显示规则**：
- 如果超额完成奖励有效，显示："超额完成！额外奖励 +6"
- 如果超额完成奖励无效，显示："达成目标！"
