**版本**: v1.0  
**创建日期**: 2026-05-26  
**负责人**: 策划团队  
**开发团队**: 前端组、游戏逻辑组

## 一、产品概述

### 1.1 产品定位

麻将24点是**To B模式专属小游戏**，作为**项目成败的裁决机制**。玩家需要通过"猜甲方心思"来赢得项目，融合麻将判定、三国杀卡牌、黑马概率三大核心机制。

### 1.2 目标用户

- 核心用户：喜欢策略博弈的玩家
- 潜在用户：对职场潜规则有共鸣的玩家

### 1.3 核心价值

- **讽刺感**：还原职场"明牌局"、"暗箱操作"等真实体验
- **策略深度**：卡牌管理 + 概率累积 + 心理博弈
- **情绪共鸣**：每个玩家都有"意外中标"或"被内定"的经历

## 二、功能需求

### 2.1 系统触发机制

#### 2.1.1 触发时机

| 触发场景 | 触发条件 | 游戏目标 | 失败后果 |
|---------|---------|---------|---------|
| **最终评审** | 项目进度满100% | 决定项目是否成功交付 | 项目失败 |
| **危机谈判** | 甲方满意度连续3周 < 50% | 决定是否能继续项目 | 甲方换人，项目失败 |

#### 2.1.2 触发逻辑

```
每次周报结算后检查：
├─ if (项目进度 >= 100%) → 触发最终评审
├─ if (甲方满意度连续3周 < 50%) → 触发危机谈判
└─ 否则 → 继续正常流程
```

### 2.2 模式判定系统

#### 2.2.1 判定流程

采用**权重随机**判定模式（不真实抽牌，避免概率计算复杂）：

```javascript
function determineMode() {
  const rand = Math.random() * 100
  if (rand < 33) {
    return 'fair' // 公平竞争 33%
  } else if (rand < 88) { // 33+55=88
    return 'undercurrent' // 暗流涌动 55%
  } else {
    return 'walkon' // 陪跑/彩蛋 12%
  }
}
```

#### 2.2.2 模式详情

| 模式 | 权重 | 甲方状态 | 乙方感受 | 三国杀 | 胜负 |
|------|------|---------|---------|----------|------|
| 🀙 公平竞争 | 33% | 真没想法 | "这次看本事了。" | ❌ | 正常博弈 |
| 🀀 暗流涌动 | 55% | 有偏好，但走流程 | "感觉怪怪的。" | ✅ | 可用卡牌 |
| 🀄 陪跑/彩蛋 | 12% | 明牌或几乎明牌 | "气氛组" / "天选之人" | ✅ | 必输/必赢 |

#### 2.2.3 彩蛋细分

陪跑/彩蛋模式需进一步判定：

| 子模式 | 概率 | 说明 | 结果 |
|---------|------|------|------|
| 明牌羞辱 | 10% | 甲方明着黑你 | **必输**，获得黑马概率+5% |
| 内定选手 | 2% | 甲方暗着帮你 | **必赢**（彩蛋） |

**判定逻辑**：

```javascript
if (mode === 'walkon') {
  const subRand = Math.random() * 100
  if (subRand < 83.3) { // 10/12 ≈ 83.3%
    return 'insult' // 明牌羞辱
  } else {
    return 'inner-determination' // 内定选手
  }
}
```

### 2.3 明牌羞辱模式（必输局）

#### 2.3.1 触发条件

权重随机 10%

#### 2.3.2 游戏流程

1. **展示阶段**：
   - 甲方**亮出所有手牌**（明牌）
   - 展示甲方的**黑幕操作**（从7种黑幕中随机选1个）

2. **决策阶段**：玩家可选择：
   - ✅ **"感谢甲方给的机会"**
     - 效果：失去1个HC（人头）
     - 奖励：**黑马概率 +5%**（跨场次累积）
     - 有5%概率立即获得"黑话牌"
   - ✅ **"尝试逆袭"**
     - 消耗：1个HC
     - 触发：**黑马判定**
     - 成功 → 意外中标（成为黑马），黑马概率清零
     - 失败 → 正常输，黑马概率继续累积
   - ❌ **"拒绝"**
     - 效果：项目失败（Game Over）

3. **结算阶段**：
   - 失去1个HC
   - 黑马概率 +5%
   - 有5%概率获得"黑话牌"

#### 2.3.3 黑马判定公式

```
黑马概率 = 玩家固有属性（初始0%，跨场次累积）
触发时机：玩家选择"尝试逆袭"时
判定公式：Math.random() * 100 < 黑马概率
成功 → 意外中标（成为黑马），黑马概率清零
失败 → 正常输，黑马概率继续累积
```

#### 2.3.4 UI要求

- **牌面展示**：甲方手牌全部明牌展示
- **黑幕文案**：用甲方口吻展示黑幕操作（参考"东南西北中发白"7种黑幕）
- **决策按钮**：3个按钮（感谢/逆袭/拒绝）
- **黑马概率进度条**：展示当前累积概率

### 2.4 暗箱模式（三国杀）

#### 2.4.1 触发条件

权重随机 55%

#### 2.4.2 游戏流程

1. **发牌阶段**：
   - 甲方手牌**背面朝上**（暗牌）
   - 玩家获得初始卡牌：杀/闪/酒 各1张（从背包携带）

2. **对战阶段**：玩家回合制
   - 玩家出牌（选择1张卡牌打出）
   - 甲方响应（AI决策）
   - 结算效果

3. **胜利条件**：
   - 甲方好感度达到100 → 赢！获得项目继续/成功
   - 玩家卡牌用完且好感度<100 → 输！项目失败

#### 2.4.3 卡牌设计

| 卡牌 | 名称 | 效果 | 消耗 | 获得方式 |
|---------|------|------|---------|----------|
| 🗡️ 杀 | 人情攻势 | 甲方好感+10 | 1张 | 背包携带 |
| 🛡️ 闪 | 关系斡旋 | 抵消一次甲方发难 | 1张 | 背包携带 |
| 🍶 酒 | 暗箱操作 | 偷看甲方1张暗牌 | 1张 | 背包携带 |

#### 2.4.4 甲方AI设计（初版简化）

```
甲方决策树：
├─ if (玩家出杀) → 好感度+10，甲方回合结束
├─ if (玩家出闪) → 甲方本回合无法发难
├─ if (玩家出酒) → 展示甲方1张暗牌，玩家获得信息
└─ 甲方回合：
    ├─ if (好感度 < 50) → 发难（玩家失去1个HC）
    └─ else → 沉默（回合结束）
```

#### 2.4.5 UI要求

- **牌桌**：甲方牌（暗）+ 玩家牌（明）
- **卡牌手牌区**：展示玩家当前持有的卡牌
- **甲方好感度条**：实时更新
- **出牌动画**：卡牌飞出效果

### 2.5 公平竞争模式（数字炸弹）

#### 2.5.1 触发条件

权重随机 33%

#### 2.5.2 游戏流程

1. **出题阶段**：
   - 系统随机生成**4个1-13的数字**（答案）
   - 系统内部验证：这4个数**能否算出24点**？（用算法验证）
   - 如果不能，重新生成（确保有解）

2. **猜测阶段**：玩家有**5次猜测机会**
   - 玩家输入4个数字
   - 系统比对：猜对了几个数字？
   - 甲方给**模糊反馈**（黑话）

3. **反馈系统**（甲方黑话映射）

| 猜测情况 | 甲方黑话 | 隐含信息 |
|---------|---------|---------|
| 猜对1个数字 | "你们关系到位了" | 有1个数字正确 |
| 猜对2个数字 | "这个方向可以" | 有2个数字正确 |
| 猜对3个数字 | "就差一点点" | 有3个数字正确 |
| 猜对4个数字 | "可以试试" | 全部正确！ |
| 数字太大 | "这个技术模型我们还需要再商讨一下" | 目标数 < 当前猜测 |
| 数字太小 | "你们方案很有创意，但..." | 目标数 > 当前猜测 |
| 完全不对 | "我们再走一下流程" | 无正确数字 |

4. **验证阶段**：猜中4个数字后，系统验证：
   - 这4个数**能否算出24点**？
   - 能 → 赢！获得项目继续/成功
   - 不能 → 输！（说明系统出bug了，保底让玩家赢）

#### 2.5.3 24点验证算法

```javascript
/**
 * 判断4个数字能否算出24点
 * @param {number[]} nums - 4个1-13的数字
 * @returns {boolean} - 是否能算出24
 */
function canMake24(nums) {
  // 全排列 + 括号组合 + 四则运算
  const permutations = getPermutations(nums) // 4! = 24种排列
  const operators = ['+', '-', '*', '/']
  const operatorCombos = getAllOperatorCombos(operators, 3) // 4^3 = 64种
  
  for (const perm of permutations) {
    for (const ops of operatorCombos) {
      // 尝试5种括号组合
      if (evalWithParentheses(perm, ops, 24)) {
        return true
      }
    }
  }
  return false
}

/**
 * 带括号的运算验证
 */
function evalWithParentheses(nums, ops, target) {
  // 5种括号组合：
  // 1. ((a op1 b) op2 c) op3 d
  // 2. (a op1 (b op2 c)) op3 d
  // 3. (a op1 b) op2 (c op3 d)
  // 4. a op1 ((b op2 c) op3 d)
  // 5. a op1 (b op2 (c op3 d))
  // 逐一计算，看是否等于target
}
```

#### 2.5.4 UI要求

- **输入区**：4个数字输入框
- **猜测次数**：显示剩余次数（5次）
- **反馈区**：甲方黑话气泡
- **24点验证动画**：猜中后，展示24点算法过程

### 2.6 黑马牌系统（核心创新）

#### 2.6.1 属性定义

- **黑马概率**：玩家固有属性，初始**0%**，**跨场次累积**
- **累积规则**：每次遇到**明牌羞辱**，+5%
- **清零规则**：**中标一次后**，概率清零（重新从0%开始累积）

#### 2.6.2 触发时机

- **主动触发**：玩家在明牌羞辱时，选择"尝试逆袭"
- **判定公式**：`Math.random() * 100 < 黑马概率`

#### 2.6.3 存储设计

```javascript
// gameState 新增字段
{
  blackHorseProbability: 0, // 黑马概率（初始0%）
  blackHorseCards: [], // 已获得的黑话牌（预留）
  // ...
}
```

#### 2.6.4 设计意图

- **讽刺感**：甲方本来没打算选你，但你"走狗屎运"中标了
- **策略深度**：玩家需要权衡"继续累积概率" vs "现在就试"
- **情绪共鸣**：职场人都有"意外中标"的经历

### 2.7 卡牌获取系统

#### 2.7.1 获取时机

**项目完成后**（无论成功/失败），根据**甲方满意度评分**奖励卡牌：

| 甲方满意度 | 奖励卡牌数 | 分配方式 |
|------------|--------------|----------|
| **≥ 90** | 5张 | 随机分配（杀/闪/酒） |
| **80-89** | 4张 | 随机分配 |
| **60-79** | 3张 | 随机分配 |
| **< 60 但完成** | 1张 | 随机分配 |
| **未完成** | 0张 | 无 |

#### 2.7.2 卡牌属性

- **类型**：杀/闪/酒
- **数量**：**消耗品**（使用后消失）
- **存储**：玩家背包（跨项目累积）
- **使用时机**：玩麻将24点时携带进入

#### 2.7.3 背包系统设计

```javascript
// gameState 新增字段
{
  cardBackpack: {
    kill: 0, // 杀（人情）数量
    dodge: 0, // 闪（关系）数量
    wine: 0   // 酒（暗箱）数量
  },
  // ...
}
```

#### 2.7.4 卡牌携带规则

- 每次玩麻将24点前，选择携带哪些卡牌
- 携带上限：杀/闪/酒 各最多3张
- 使用后消失，需通过项目奖励补充

## 三、非功能需求

### 3.1 性能要求

- 24点验证算法需在**100ms内**完成
- 模式判定、卡牌结算等逻辑需**无卡顿**

### 3.2 兼容性

- 支持主流浏览器（Chrome、Firefox、Safari、Edge）
- 支持移动端（响应式布局）

### 3.3 数据持久化

- 黑马概率、卡牌背包需**跨场次保存**（localStorage）
- 每局游戏结束后自动存档

## 七、风险与应对

### 7.1 技术风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 24点验证算法性能问题 | 玩家体验卡顿 | 提前优化算法，必要时限制数字范围（1-10） |
| 甲方AI决策树过于简单 | 游戏性不足 | MVP版本先用简单AI，后续迭代复杂AI |

### 7.2 设计风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 明牌羞辱模式导致玩家挫败感强 | 玩家流失 | 加入"黑马概率"机制，给玩家逆袭希望 |
| 卡牌获取速度过慢 | 玩家长期无卡牌可用 | 调整满意度奖励概率，或加入卡牌购买功能 |
