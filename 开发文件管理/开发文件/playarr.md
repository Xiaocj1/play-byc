## 核心数值系统

### 三模式统一数值
- **资金（Budget）**：收入来源（回款/收入/抽成），支出工资、抽卡、事件
- **名声（Fame）**：影响报表奖励、抽卡成本、负债上限、利率
- **负债（Debt）**：可借额度由名声决定，每周利息，资金归零且无法借款时破产

### 项目进度
- **初始值**: 0%
- **最大值**: 100%
- **显示格式**: `XX.XX% (阶段名称·SDLC-0X)`
- **完成动画**: 100%时触发彩虹流动效果

### 甲方满意度（To B）
- **初始值**: 80%
- **范围**: 0-100%
- **失败条件**: 连续3周低于65%

### 团队好感度
- **初始值**: 50%
- **范围**: 0-100%
- **效率buff触发**: >80%时触发

### 方向特定指标

#### To B 模式
| 指标 | 说明 |
|------|------|
| 标杆客户数 | 成功交付的客户数量 |
| 满意度 | 甲方对项目的满意程度 |
| 续约率 | 下个项目是否续约的概率 |

#### To C 模式
| 指标 | 说明 |
|------|------|
| DAU | 日活跃用户数 |
| LTV | 用户生命周期价值 |
| 留存率 | 用户留存情况 |

#### B2C 模式
| 指标 | 说明 |
|------|------|
| GMV | 商品交易总额 |
| 抽成率 | 平台抽取的佣金比例 |
| 纠纷率 | 交易纠纷发生率 |

## 创业方向系统

### 开局三选一
玩家在游戏开始时选择创业方向：
- **To B（企业服务）**：对接企业甲方，分阶段回款
- **To C（消费者应用）**：面向个人用户，DAU驱动收入
- **B2C（平台电商）**：连接服务商与用户，GMV抽成

### 方向影响
- 影响核心指标体系
- 影响任务来源和类型
- 影响结局文案
- 共用资金、名声、负债、抽卡、报表系统

## 报表与谈判对决系统

### 三局两胜制
每季度末进行报表对决，决定下季度 OKR 加点

### 四类卡牌岗位
| 岗位 | 说明 |
|------|------|
| 运营 | 负责增长和用户运营 |
| 设计 | 负责UI/UX设计 |
| QA | 负责质量保证和测试 |
| RD | 负责技术开发 |

### 克制链
```
运营 → 设计 → QA → RD → 运营
```
- 克制方胜利，不损耗卡牌
- 被克制方失败，卡牌磨损 -1
- 磨损归零则卡牌销毁（离职/考公）

### 战力比拼
当双方岗位不存在克制关系时，进行战力比拼：
- 卡牌战力 = 星级 × (1 + 效率加成)
- 战力高者获胜

### 谈判点数
每季度谈判获胜可获得谈判点数，影响下季度 OKR 加点

### 配置文件
`data/cards.json`

## 收入与运营模式

### To B（分阶段回款）
```
收入 = 项目基数 × 阶段比例 × 满意度系数
```
- **阶段比例**：30% → 40% → 30%（3-4-3模式）
- **满意度系数**：0.5 + (满意度 / 100)
- **项目续约**：续约率高可能获得2.0升级项目（进度+30%）

### To C（季度收入结算）
```
季度收入 = DAU × LTV × (季度天数 / 365)
```
- LTV 默认值：1万元
- 季度天数：90天

### B2C（季度收入结算）
```
季度收入 = GMV × 抽成率
```
- 默认抽成率：5%
- GMV 单位：亿元

## 合同与风险系统

### 合同续约机制（仅 To B）
- **续约率**：影响下个项目是2.0升级还是全新项目
- **2.0项目**：进度直接+30%

### 撕合同条件
满足以下任一条件，甲方可能撕毁合同：
- 满意度 < 25%
- 连续两季度进度 < 50%
- 多次硬刚甲方

### 撕合同后果
- 赔偿金扣除
- 名声大降
- 好感度下降
- 甲方黑名单

### To C 风险事件
- 用户流失
- 买量成本飙升
- 监管下架
- 版本被应用商店下架

### B2C 风险事件
- 服务商抗议
- 用户投诉暴增
- 纠纷率过高
- 监管部门约谈
- 竞争对手降价

## 抽卡与招募系统

### 抽卡规则
- 四岗位（运营、设计、QA、RD）
- 抽卡消耗资金
- 成本受名声影响

### 特殊卡牌
| 类型 | 说明 |
|------|------|
| 管培生 | 不占HC，可变异或考公/跑路 |
| 外包兄弟 | 有副作用 |

### 管培生变异机制
管培生抽到后不会立即加入背包，需要经历培养期：
- **培养时间**：至少3个月（12周）
- **报表考核**：度过至少一次报表周期
- **变异时机**：报表结束后检查是否满足条件

**变异规则**：
1. 抽到管培生后，加入 `pendingVariants` 培养列表
2. 记录抽卡时的周数和报表次数
3. 每次报表结束时检查：
   - 是否已满3个月（12周）
   - 是否经历了至少一次报表（`totalReports - drawnReportCount >= 1`）
4. 满足条件则变异为正式卡牌，加入背包
5. 变异结果随机，可能是不同稀有度的正式员工

**特殊结果**：
| 结果类型 | 说明 |
|----------|------|
| 跑路（runaway） | 管培生直接跑路，获得少量资金补偿 |
| 考公（exam） | 管培生考上公务员，获得资金奖励 |
| 变异成功 | 成为正式员工，稀有度随机 |

### 卡牌用途
- 解决报表待办
- 谈判对决
- 执行任务

### 星级与战力
| 星级 | 基础战力 |
|------|----------|
| ⭐ | 1.0 |
| ⭐⭐ | 1.5 |
| ⭐⭐⭐ | 2.0 |
| SSR | 3.0 |

## 好感度与效率系统

### 效率Buff触发
- **触发条件**: 好感度 > 80%

- **持续时间**: 永久（直到好感度降至80%以下）

```javascript
efficiency = 1 + randomBonus(0.05, 1.0) + buffEffects
```

- 保留最近5周的好感度记录

## 结局系统

### 胜利条件

#### 上市敲钟
- **条件**：资产 ≥ 2000万 + 市场地位达标
  - To B：5个标杆客户
  - To C：DAU > 500万
  - B2C：GMV > 10亿

#### 闷声发财
- **条件**：资产 ≥ 1000万 + 连续2年盈利 + 玩家主动拒绝上市

#### 被收购
- **条件**：资产 ≥ 500万 + 市场地位达标 + 触发收购事件

### 失败条件

#### 破产清算
- **条件**：资金 ≤ 0 且 负债已达上限

#### 产品凉了（To C）
- **条件**：DAU = 0

#### 平台崩盘（B2C）
- **条件**：纠纷率 > 30%

### 结局文案风格
- 黑色幽默
- 拒绝温情鸡汤
- 反映创业现实

## PMF关键事件系统

### 系统概述
PMF（Product-Market Fit，产品市场契合度）关键事件系统是ToC模式的核心机制，模拟创业公司在找到产品市场契合点后面临的发展战略选择。

### PMF判定条件
当ToC模式中同时满足以下条件时，触发PMF关键事件：
- **DAU ≥ 50万**（日活跃用户数）
- **LTV ≥ 20元**（用户生命周期价值）

### 触发机制
1. **检查时机**：每周调用 `handleWeekChange()` 时检查PMF条件
2. **事件触发**：满足条件后，游戏自动暂停
3. **UI展示**：弹出PMF选择模态框，背景模糊，禁用所有游戏按钮
4. **强制选择**：玩家必须做出选择才能继续游戏

### 关键事件场景
采用委婉的发展理念表达方式，通过团队会议讨论的场景呈现：

```
团队会议上，大家正在讨论下一步战略方向。产品已经找到了PMF
（产品市场契合点），用户开始自发传播，增长曲线开始上扬。
现在面临关键抉择：
```

### 三种增长策略

#### 1. 🚀 激进增长路线
- **理念表达**："先占领市场，钱的事以后再说！"
- **DAU增长倍数**：×2.0
- **LTV增长倍数**：×0.8
- **胜利条件**：DAU > 500万
- **适合玩家**：追求规模效应，计划融资或IPO
- **风险**：变现能力不足，资金压力大

#### 2. 💰 深度变现路线
- **理念表达**："先让产品值钱，让用户愿意付费！"
- **DAU增长倍数**：×0.8
- **LTV增长倍数**：×2.0
- **胜利条件**：LTV > 200元
- **适合玩家**：追求盈利能力，现金流健康
- **风险**：增长放缓，可能被竞争对手超越

#### 3. ⚖️ 平衡发展路线
- **理念表达**："既要增长也要盈利，走长期主义路线！"
- **DAU增长倍数**：×1.2
- **LTV增长倍数**：×1.2
- **胜利条件**：DAU > 100万 且 LTV > 50元
- **适合玩家**：稳健经营，追求长期价值
- **风险**：相对平衡，风险可控

### 增长倍数应用
选择策略后，增长倍数会应用到DAU和LTV的计算中：

```javascript
// DAU计算（应用增长倍数）
const dauGrowth = baseGrowth + (progress * 0.1) + (satisfaction * 0.5) + okrBonus * 2 - Math.random() * 3;
gameState.dau = Math.max(0, Math.round(gameState.dau + dauGrowth * dauMultiplier));

// LTV计算（应用增长倍数）
const ltvBase = 2 + (satisfaction * 0.05);
gameState.ltv = Math.max(1, Math.round(ltvBase * ltvMultiplier));
```

### 游戏流程控制
1. **暂停机制**：PMF事件触发后，自动禁用所有游戏按钮
2. **背景效果**：主游戏区域添加模糊效果，突出模态框
3. **强制选择**：不允许关闭模态框，必须做出选择
4. **恢复机制**：选择完成后，恢复游戏按钮和逻辑

### 相关字段（gameState）
```javascript
{
  pmfReached: false,        // 是否已达到PMF
  pmfChoiceMade: false,     // 是否已经做出关键选择
  growthStrategy: null,      // 增长策略：'aggressive'/'monetization'/'balanced'
  dauMultiplier: 1.0,      // DAU增长倍数
  ltvMultiplier: 1.0       // LTV增长倍数
}
```

## 任务系统

### 任务类型
游戏中有多种任务类型，对应不同岗位：
- **RD任务**：紧急Bug修复、性能优化等
- **QA任务**：压力测试、回归测试等
- **运营任务**：用户调研、活动策划等
- **设计任务**：UI改版、品牌设计等
- **产品任务**：需求评审、PRD撰写等

### 任务机制
- **难度等级**：简单、中等、困难
- **耐久消耗**：1-2点耐久度
- **成功率**：根据难度和卡牌稀有度计算
- **稀有度加成**：SR+10%，SSR+20%

### 执行流程
1. 点击「📋 任务」按钮打开任务列表
2. 查看可用任务（未完成的任务）
3. 选择对应岗位的员工执行
4. 消耗耐久度，获得奖励或承受惩罚

### 磨损机制
- 每次执行任务消耗卡牌耐久度
- 耐久度耗尽时，卡牌消失（员工离职）
- 需要谨慎选择执行任务的员工

### 任务效果
- **成功**：获得进度、满意度、名声、资金等奖励
- **失败**：可能扣除满意度、资金等

`data/missions.json`

## 修改指南

### 调整项目进度速度
修改 `data/weights.json` 中的权重值

### 添加新Buff
在 `data/buffs.json` 的 `buffs` 数组中添加新对象

### 调整职级系统
修改 `data/ranks.json` 中的职级配置

### 添加新工具
在 `data/tools.json` 对应类别的 `tools` 数组中添加

### 添加新卡牌
在 `data/cards.json` 的 `pools` 数组中添加，注意设置 `position` 字段

### 添加方向事件
在 `data/events.json` 的 `events` 数组中添加，添加 `direction` 字段指定适用的创业方向

### 添加融资轮次
在 `data/financing.json` 的 `rounds` 数组中添加新轮次配置

### 添加产品图鉴
在 `data/products.json` 的对应分类数组中添加，设置解锁条件和三重声音

### 添加结局图鉴
在 `data/ending_gallery.json` 的 `endings` 数组中添加，设置 `type`（victory/failure）和 `direction`

### 添加真实失败产品
在 `data/real_failed_products.json` 的 `real_failed_products` 数组中添加，默认全部解锁

### 添加任务
