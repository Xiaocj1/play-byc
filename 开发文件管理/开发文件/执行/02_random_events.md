# 纯偶发事件系统（无选项版）

## 功能描述
引入无选项偶发事件，作为现有选择事件的补充，增加游戏随机性和沉浸感。事件触发后自动应用效果，无需玩家选择。

## 关键词池
keywords:
  - 偶发事件
  - 无选项事件
  - 自动效果

locked_keywords:
  - 为偶发事件添加选项
  - 移除现有选择事件

emphasis_keywords:
  - 事件触发概率控制在20%-30%
  - 必须支持模式差异化（ToB/ToC/B2C不同主题）

## 数据定义
**事件类型：**

| 类型 | 触发时机 | 效果特点 | 示例场景 |
|------|---------|---------|---------|
| **环境事件** | 每周随机（20%概率） | 轻微正面/负面效果 | 天气影响、办公室氛围 |
| **机遇事件** | 进度里程碑、高满意度 | 纯正面效果 | 意外收获、免费资源 |
| **危机事件** | 低满意度、随机触发 | 纯负面效果 | 突发故障、意外开支 |
| **彩蛋事件** | 特定条件触发 | 趣味性效果 | 节日彩蛋、隐藏剧情 |

**事件数据结构：**
```json
{
    "id": "random_event_001",
    "title": "阳光明媚的一天",
    "type": "environment",
    "triggerCondition": {
        "probability": 0.2,
        "minWeek": 1,
        "maxWeek": 52
    },
    "autoEffects": {
        "morale": 3
    },
    "weeklyEffect": "团队士气略有提升"
}
```

**触发机制：**
```
每周开始时：
  ├─ 检查偶发事件触发条件
  │   ├─ 随机概率判定（20%-30%）
  │   └─ 满足特定条件（满意度、进度、周数等）
  ├─ 若触发成功：
  │   ├─ 显示事件弹窗（仅展示，无选项按钮）
  │   ├─ 自动应用效果到游戏状态
  │   └─ 记录到周日志
  └─ 继续正常事件流程
```

**模式差异化设计：**

| 模式 | 环境事件主题 | 机遇事件主题 | 危机事件主题 |
|------|-------------|-------------|-------------|
| **ToB** | 甲方来访、合同审批、招标信息 | 客户转介绍、合同续签、政策利好 | 客户投诉、项目延期、回款困难 |
| **ToC** | 应用商店推荐、社区热议、KOL关注 | 下载量爆发、好评如潮、融资机会 | 应用下架、服务器崩溃、负面报道 |
| **B2C** | 商家入驻、流量增长、政策支持 | 头部商家入驻、GMV突破、品牌合作 | 商家抗议、用户投诉、监管约谈 |

## 负面影响评估
risks:
  - risk: "偶发事件过于频繁，打断正常流程"
    severity: 中
    mitigation: "设置触发冷却，同一类型事件每周最多触发1次"
  - risk: "负面事件过多，玩家挫败感强"
    severity: 中
    mitigation: "控制负面事件比例不超过30%"

## 验收标准
- [ ] 事件数据结构调整，支持triggerCondition字段
- [ ] 每周有20%-30%概率触发偶发事件
- [ ] 事件触发后自动应用效果，无选项按钮
- [ ] 事件效果正确记录到周日志
- [ ] ToB/ToC/B2C三种模式有不同的事件主题
