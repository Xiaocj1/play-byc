# 商家揽客小游戏 - 玩法优化评审（v1.0）

> 评审对象：《PRD修改回应文档（v3.0）》中的"商家揽客小游戏"设计  
> 评审焦点：**如何做得更好玩**（而非是否要做）  
> 评审日期：2026年5月  
> 评审版本：v1.0

---

## 一、现有设计分析

### 1.1 当前设计方案

**游戏机制**：
```
1. 展示3张商家卡牌（普通/优质/头部商家）
2. 玩家选择一张进行洽谈
3. 显示商家需求（资金补贴、流量支持、技术服务）
4. 玩家分配资源（资金、流量、人力）来满足需求
5. 资源匹配度+角色好感度决定成功率
6. 成功匹配则商家入驻，失败则商家离开
```

**核心玩法**：资源分配 + 概率判定

### 1.2 优缺点分析

| 优点 | 缺点 |
|------|------|
| ✅ 机制简单易懂 | ❌ 玩法单一，缺乏策略深度 |
| ✅ 与B2C模式契合 | ❌ 缺少反馈和爽感 |
| ✅ 实现成本可控 | ❌ 重复可玩性低 |
| | ❌ 缺少竞争和紧急感 |

## 二、玩法优化方案

### 2.1 方案A：卡牌谈判系统 ⭐⭐⭐⭐⭐（推荐）

**核心机制**：将谈判过程改为**卡牌对战**形式

#### 游戏流程：
```
1. 【发牌阶段】玩家从"谈判牌库"中抽取3张手牌
2. 【商家出招】商家展示"需求牌"（资金/流量/技术）
3. 【玩家出牌】玩家选择手牌应对（可出1-3张）
4. 【判定阶段】卡牌效果 + 资源匹配度 + 好感度 = 成功率
5. 【奖励阶段】成功则商家入驻，获得奖励
```

#### 卡牌设计：

**谈判牌库**（玩家使用）：
| 卡牌名称 | 类型 | 效果 | 稀有度 |
|---------|------|------|--------|
| 价格战 | 资金 | 资金需求-50% | R |
| 流量扶持 | 流量 | 流量需求-50% | R |
| 技术支持 | 技术 | 技术需求-50% | R |
| 组合拳 | 组合 | 随机降低两项需求 | SR |
| 杀手锏 | 特殊 | 成功率直接+30% | SR |
| 必杀技 | 特殊 | 本次谈判必定成功 | SSR（限1次） |

**需求牌**（商家出）：
| 需求类型 | 资金需求 | 流量需求 | 技术需求 | 基础成功率 |
|---------|---------|---------|---------|-----------|
| 普通商家 | 5 | 3 | 2 | 80% |
| 优质商家 | 8 | 5 | 4 | 60% |
| 头部商家 | 12 | 8 | 6 | 40% |

#### 成功率计算公式（优化后）：
```
最终成功率 = 基础成功率 
              + 卡牌效果加成 
              + 资源匹配度加成（每项满足+10%） 
              + 小葵好感度加成（≥80时+10%） 
              + 连击加成（连续成功+5%/次，最高+15%）

上限：95%
下限：5%
```

#### 视觉反馈优化：
1. **发牌动画**：卡牌从牌库飞入玩家手牌区
2. **出牌动画**：玩家拖拽卡牌到"谈判桌"
3. **判定动画**：转盘/骰子动画显示成功率
4. **结果动画**：
   - 成功：商家笑脸 + 礼花动画 + "入驻成功"特效
   - 失败：商家离开 + 叹气动画 + "再接再厉"提示

#### 实现成本：
- **高**：需要设计卡牌系统、动画系统、UI界面
- **预计工作量**：5-7天

### 2.2 方案B：竞价拍卖系统 ⭐⭐⭐⭐（备选）

**核心机制**：引入**竞争元素**，其他平台也在抢商家

#### 游戏流程：
```
1. 【招商会开始】3家商家 + 2个竞争对手（AI）
2. 【竞价阶段】每轮玩家和AI同时出价（资金/流量/技术）
3. 【商家选择】商家选择"综合评分"最高的平台
4. 【结算阶段】成功则商家入驻，失败则资金/资源损失
```

#### 竞价机制：
| 资源类型 | 玩家出价 | AI出价 | 商家偏好 |
|---------|---------|---------|---------|
| 资金补贴 | 玩家输入 | AI随机 | 普通商家：资金>流量>技术 |
| 流量支持 | 玩家输入 | AI随机 | 优质商家：流量>技术>资金 |
| 技术服务 | 玩家输入 | AI随机 | 头部商家：技术>资金>流量 |

#### 竞争元素：
- **AI难度递增**：第1季度AI出价保守，第4季度AI出价激进
- **商家个性**：部分商家"嫌贫爱富"（只接受最高出价），部分商家"看重服务"（考虑技术+流量）
- **情报系统**：可以花费"情报点"查看AI出价范围

#### 实现成本：
- **中**：需要设计AI逻辑、竞价UI、商家个性系统
- **预计工作量**：3-5天

### 2.3 方案C：经营模拟系统 ⭐⭐⭐（备选）

**核心机制**：将招商会改为**简化版经营模拟**

#### 游戏流程：
```
1. 【选择商家】玩家选择要招募的商家类型
2. 【经营阶段】玩家分配"资金、流量、技术"到3个区域
3. 【随机事件】每季度触发1个随机事件（政策变化、市场波动等）
4. 【结算阶段】经营收益>商家期望 → 入驻成功
```

#### 经营模拟：
| 区域 | 投入资源 | 可能收益 | 风险 |
|------|---------|---------|------|
| 门店装修 | 资金 | 商家好感度+10 | 装修失败（资金损失） |
| 线上推广 | 流量 | 用户转化率+5% | 推广无效（流量浪费） |
| 技术支持 | 技术 | 平台稳定性+10% | 技术故障（商家离开） |

#### 实现成本：
- **高**：需要设计经营系统、随机事件库、收益计算
- **预计工作量**：7-10天

## 四、最终推荐：方案A（卡牌谈判系统）

### 4.1 为什么选择方案A？

1. **趣味性强**：卡牌收集+组合+对战，玩家有"爽感"
2. **策略深度足**：需要权衡手牌使用、资源分配、成功率计算
3. **与现有系统联动好**：可以复用卡牌系统的"抽卡"、"装备"逻辑
4. **重复可玩性高**：卡牌组合多样，每次谈判都有新鲜感

### 4.2 方案A的详细设计

#### 4.2.1 谈判牌库设计

**卡牌获取方式**：
1. **抽卡**：消耗"招商券"（每季度第6周自动获得1张）
2. **合成**：3张同类型R卡 → 1张SR卡
3. **奖励**：成功招募商家后，概率获得卡牌

**卡牌类型**：
| 类型 | 卡牌名称 | 效果 | 稀有度 | 获取方式 |
|------|---------|------|--------|---------|
| 资金类 | 价格战 | 资金需求-50% | R | 抽卡/合成 |
| 资金类 | 补贴大战 | 资金需求-80% | SR | 合成/奖励 |
| 流量类 | 流量扶持 | 流量需求-50% | R | 抽卡/合成 |
| 流量类 | 爆款打造 | 流量需求-80% | SR | 合成/奖励 |
| 技术类 | 技术支持 | 技术需求-50% | R | 抽卡/合成 |
| 技术类 | 黑科技 | 技术需求-80% | SR | 合成/奖励 |
| 组合类 | 组合拳 | 随机降低两项需求 | SR | 奖励 |
| 特殊类 | 杀手锏 | 成功率直接+30% | SR | 奖励 |
| 特殊类 | 必杀技 | 本次谈判必定成功 | SSR | 成就奖励 |

#### 4.3.2 核心函数设计

**新增文件**：`js/merchant_game.js`

**核心函数**：
```javascript
// 开始招商会
function startMerchantRecruitment() {
    if (gameState.direction !== 'b2c') return;
    
    // 生成3家商家
    const merchants = generateMerchants(3);
    
    // 玩家抽3张手牌
    const hand = drawNegotiationCards(3);
    
    // 存储游戏状态
    gameState.currentMerchantGame = {
        merchants: merchants,
        hand: hand,
        allocatedFunding: 0,
        allocatedTraffic: 0,
        allocatedTech: 0,
        combo: gameState.merchantCombo || 0
    };
    
    // 渲染游戏界面
    renderMerchantGame();
}

// 抽取谈判卡牌
function drawNegotiationCards(count) {
    const cardPool = data.negotiationCards.cards;
    const hand = [];
    
    for (let i = 0; i < count; i++) {
        const card = cardPool[Math.floor(Math.random() * cardPool.length)];
        hand.push({ ...card });
    }
    
    return hand;
}

// 使用卡牌
function useNegotiationCard(cardId) {
    const game = gameState.currentMerchantGame;
    const cardIndex = game.hand.findIndex(c => c.cardId === cardId);
    
    if (cardIndex === -1) return;
    
    const card = game.hand[cardIndex];
    
    // 应用卡牌效果
    applyCardEffect(card);
    
    // 从手牌中移除
    game.hand.splice(cardIndex, 1);
    
    // 重新渲染
    renderMerchantGame();
}

// 应用卡牌效果
function applyCardEffect(card) {
    const game = gameState.currentMerchantGame;
    const merchant = game.selectedMerchant;
    
    if (!merchant) return;
    
    switch (card.effect) {
        case 'reduce_funding_req':
            merchant.fundingReq *= (1 - card.value);
            break;
        case 'reduce_traffic_req':
            merchant.trafficReq *= (1 - card.value);
            break;
        case 'reduce_tech_req':
            merchant.techReq *= (1 - card.value);
            break;
        case 'add_success_rate':
            game.successRateBonus += card.value;
            break;
    }
}

// 确认洽谈
function confirmNegotiation(merchantId) {
    const game = gameState.currentMerchantGame;
    const merchant = game.merchants.find(m => m.id === merchantId);
    
    if (!merchant) return;
    
    // 计算成功率
    let successRate = merchant.baseSuccessRate;
    
    // 卡牌效果加成（已在useNegotiationCard中应用）
    successRate += game.successRateBonus;
    
    // 资源匹配度加成
    const fundingMet = game.allocatedFunding >= merchant.fundingReq;
    const trafficMet = game.allocatedTraffic >= merchant.trafficReq;
    const techMet = game.allocatedTech >= merchant.techReq;
    const matchCount = [fundingMet, trafficMet, techMet].filter(Boolean).length;
    successRate += matchCount * 0.1;
    
    // 小葵好感度加成
    const xiaokuiFavor = gameState.characterFavors?.xiaokui || 0;
    if (xiaokuiFavor >= 80) successRate += 0.1;
    
    // 连击加成
    successRate += game.combo * 0.05;
    
    // 上限95%
    successRate = Math.min(successRate, 0.95);
    
    // 判定
    if (Math.random() < successRate) {
        // 成功
        gameState.merchantCount += merchant.reward;
        gameState.morale += 5;
        gameState.merchantCombo = (gameState.merchantCombo || 0) + 1;
        
        showNotification(`🎉 ${merchant.name}成功入驻！商家数+${merchant.reward}`);
        
        // 概率获得卡牌
        if (Math.random() < 0.3) {
            const rewardCard = drawNegotiationCards(1)[0];
            gameState.negotiationHand.push(rewardCard);
            showNotification(`🎁 获得卡牌：${rewardCard.name}`);
        }
    } else {
        // 失败
        gameState.morale -= 3;
        gameState.budget -= 5;
        gameState.merchantCombo = 0;
        
        showNotification(`😔 ${merchant.name}拒绝入驻`);
    }
    
    // 扣除资源
    gameState.budget -= game.allocatedFunding * 2;
    
    // 关闭游戏界面
    closeMerchantGame();
}
```

## 六、评审结论

### 6.1 原方案问题
1. ❌ **玩法单一**：纯资源分配，缺乏策略深度

3. ✅ **与现有系统联动好**：复用卡牌系统逻辑
